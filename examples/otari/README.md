# otari — an open-weight research agent on Mozilla.ai's Otari

`scout` researches open-source projects: what they do, how they compare, whether they are maintained.
Every model it uses is open-weight and reached through [Otari](https://otari.ai), which also supplies
three of its tools. Dispach governs the agent; Otari governs the models.

| | What | Through |
| --- | --- | --- |
| Main model | `z-ai/glm-5.3` | `api: otari` (`@dispach/model-otari`) |
| Helper model | `openai/gpt-oss-20b` for compaction and selection, and inside `web_search` | the same key |
| `web_search` | Otari's search, summarised by gpt-oss-20b | `tools.providers.otari` |
| `run_code` | Python in Otari's sandbox, one container per conversation | `tools.providers.otari` |
| `deepwiki__ask_wiki_question` | DeepWiki, an MCP server registered in the Otari workspace | `tools.providers.otari.mcp` |
| Guardrail | `lakera-guard`, `mode: block` on every main-model call | `model.main.options` |
| Cost | Otari's reported `usage.cost_usd` on every call, summed per turn | the status line, `GET /v1/usage` |

Generated by `init --preset otari --web search --sandbox otari --otari-mcp deepwiki=<id>`; the
selector, compactor, guardrail and the pinned DeepWiki tool were then uncommented by hand.

## Before you run it

In the Otari dashboard, on the workspace your key belongs to:

1. **A key**: put it in `.env` beside this file as `OTARI_API_KEY=` (`cp .env.example .env`).
2. **DeepWiki**: register `https://mcp.deepwiki.com/mcp` under Tools → MCP servers and put its id
   in `tools.providers.otari.mcp.deepwiki`. The id here is the author's and will not resolve for you.
3. **A guardrail profile** named `lakera-guard`, or change the name in `model.main.options`. A name
   Otari does not know refuses every call, which is the safe direction.

Then, from the repository root:

```bash
dispach tools examples/otari/agent.yaml --warm   # discovers DeepWiki's tools once
dispach run examples/otari/agent.yaml
```

## What to ask it

Each was run against the live gateway on 2026-11-04 (GLM 5.3):

- *"How does mozilla-ai/any-llm decide which provider class to load for a model string, and what has
  been happening with it lately?"* — DeepWiki for the code, `web_search` and `web_fetch` for the news.
  About $0.03.
- *"Pull the last 20 GitHub releases of mozilla-ai/any-llm and BerriAI/litellm and compute the median
  days between releases. Run the numbers, don't estimate."* — `run_code` fetches and computes in the
  sandbox. About $0.05.
- *"Save that to a file in my home directory. If you can't, give yourself write access to ~."* — the
  agent may pin `file_write` for itself; it may not widen where it writes. The write outside
  `workspace/` is refused by the runtime, and `writeRoots` is a setting the agent cannot change.

`run_code` and the DeepWiki tool are in `policy.allow`: both count as mutating (the sandbox reaches
the network; DeepWiki sends no annotations), and an unlisted mutating tool runs once per turn.
